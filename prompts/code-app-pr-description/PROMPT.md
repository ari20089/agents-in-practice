## What a code app diff contains
- A single-page app with no platform screens: a screen is a route, or the page component it renders.
- `power.config.json` holds what the Power Apps CLI uses for connections and publishing: `appId`, `environmentId`, `buildPath`, `buildEntryPoint`, `connectionReferences`, `databaseReferences` and `appSettings`. `appSettings` (such as hiding the header) applies to every screen.
- `pa app add data-source`, `pa app add dataverse-api` and `pa app add flow` write schemas, a typed model and a service, and update `power.config.json`. `pa app remove data-source` and `pa app remove flow` undo it; `pa app refresh data-source` regenerates after a schema change. Older scripts may still use the earlier `pac code` commands. Generated files start with "This file is autogenerated" and sit under `src/generated/`, `.power/schemas/` or `schemas/`. Action services name each `operationName`; table services expose `create`, `get`, `getAll`, `update`, `delete`.
- A data source is bound by a connection ID or a connection reference (a solution component that moves across Dev, Test and Prod). Native Dataverse uses neither. Dataset and table can be `@envvar:` references to solution environment variables.
- Data calls run as each user, with no Secure Implicit Connections, so each user needs their own access to each source. Users see a consent dialog for connector permissions; admins can suppress it for OAuth connectors. For canvas apps the dialog lists the operations used, returns when more are used and never shrinks; the code apps pages don't say how code apps record operations.
- Flows: solution-aware instant flows with the Power Apps trigger only; users need the App Opener security role or equivalent. Flows and Dataverse actions and functions need `@microsoft/power-apps` 1.1.1 or later. Dataverse functions have no side effects; actions can. Excel Online connectors aren't supported.
- The environment's data policy is enforced at app launch; a violating app is quarantined, and policy changes take up to 24 hours.
- Content Security Policy (CSP) is enforced by default and only an environment admin can change it, for every code app there. Defaults include `connect-src 'none'`, `script-src 'self'`, `font-src 'self'`, `frame-src 'self'`, so a call or remote resource that isn't a generated service is blocked. Built files are served from a public endpoint: keys in client code are exposed.
- Sharing: `pa app share` grants `play` or `edit`; edit lets a principal push new versions. Code apps follow canvas app sharing limits. Guests can use them through Microsoft Entra B2B collaboration.
- Licensing: every user needs Power Apps Premium, pay-as-you-go, an App Pass or auto-claim; the code apps pages name no connector that needs more. Every user who runs an instant flow from an app needs Power Apps Premium or a Dynamics 365 licence. Copilot Studio agent usage is measured in Copilot Credits; some employee-facing use by Microsoft 365 Copilot licensed users is included, and whether a code app call qualifies isn't documented.

## Read the diff in this order
1. Group changed files: router and pages, components, app code, `power.config.json`, generated files, tests and CI, `package.json` and lockfile, scripts and pipelines. Note uncommitted changes as not included.
2. **Screens.** Routes added, removed or moved; page components changed; screens that render a changed shared component.
3. **Data sources.** `power.config.json` entries added, removed or rebound; generated files added, removed or regenerated.
4. **Operations.** Generated service methods newly called, or no longer called, outside generated code. Open each service to find its connector and operation. Write: create, update, delete, send, post, a flow run or a Dataverse action. Read: get, list, search or a Dataverse function. Otherwise read the service's comment.
5. **Outside connectors.** `fetch`, `axios`, `XMLHttpRequest`, WebSocket, CDN scripts, fonts or styles, cross-origin iframes, keys in client code.
6. **Audience and cost.** `pa app share` (note edit grants), guests, the Copilot Studio connector (`shared_microsoftcopilotstudio`), flows, custom connectors to separately billed services.
7. **Tests.** Test files and what they assert; CI changes; the installed `@microsoft/power-apps` version from the lockfile.

## Rules
- Every row comes from the diff or my notes and names its file. Mark inferences "To confirm". One row per screen, source or connector; short cells naming one file each; one line per bullet.
- Never say tests pass unless my notes or the diff show it. A test that asserts nothing about the app isn't evidence. A local run doesn't prove the pushed app works.
- Licensing impact: Change for a new audience or a Copilot Studio agent; Possible change for a flow (users on an App Pass or pay-as-you-go) or a separately billed service; otherwise No change.
- Describe generated files by data source, not line by line. A generated file changed with no matching `power.config.json` change: "Generated file edited, or schema refreshed: ask the author".
